# RecompDev workspace/v0.4.9.5 — live controller execution monitor

**Release date:** 2026-11-05. **Scope:** source-only orchestration and read-only diagnostics. No native-controller, CPU plugin or host DLL rebuild.

## Contract

The **controller-owned** `controller_diagnostics` service exposes a versioned, authenticated local event subscription. `execution_monitor` is a separate desktop process and communicates **only** with the controller service. Hardware/CPU adapters publish typed events to the service via the native launcher. The service coordinates delivery, not instruction decoding. Generated translated C++ and all protected historical files are not modified.

`Run-Native-Game.ps1 -ExecutionMonitor [-MonitorEvery 256]` enables live sampled instruction PC/opcode/class, SP, cycles, steps, frames, input and stop diagnostics. Default sample interval is 256; 1 captures each transition **until** the 200,000-event safety cap (potentially significant slowdown), not an unlimited complete trace. The monitor shows a rolling recent history. The event journal and viewer log go into the existing evidence ZIP, along with the runtime report. Tkinter on the owner Windows machine must be verified.

The **compiled** `RecompDev.exe` still routes preserved services, and remains at version 0.4.4. The controller diagnostic broker is currently a Python service launched by the runtime orchestrator; it is not yet an ABI exposed by the compiled controller. This is explicitly an intermediate boundary, not a claim of full production-plugin unification. No monitor-to-plugin calls exist. No pause/step/resume/breakpoints implemented yet; no full Z80 disassembly implemented. No ROM independence or independent gameplay parity established.

## Additional prerequisite correction

The movement recorder's established frame interface accepts guest cycles, frame, VRAM and VDP registers (four arguments). A provisional v0.4.9.5 change wrongly added RAM as a fifth argument and failed to compile; the corrected release retains the four-argument call. Work RAM is independently sampled through `rd_sms_memory_adapter::sample(...)`. The staging and compiled-game tests assert both paths; original translator, native CPU instruction generation and 642 historical files remain unchanged. The WindowsFix3 packaging also surfaces native compiler stdout/stderr when generated-app tests fail. Owner Windows acceptance is still required.
