## Changes

1. **Native Win32 execution monitor:** `RecompDevMonitor.exe` (standalone build target) uses a read-only, bounded, authenticated localhost event subscription to the existing controller diagnostics schema. Its display is CPU/platform-neutral; it does not load ROMs, guest CPU/machine DLLs, or disassemble CPU instructions. The compiled controller passes the exact adjacent exe path. The current preview **does not** spawn `execution_monitor.viewer` or Python/Tk, although temporary Python orchestration, analysis, and source instrumentation remain present. Windows owner visual acceptance is pending.
2. **Three native clock values:** Source-verified, generated native application emits `guest_frames` from its terminal VDP state in addition to `frames` from host output. Preview diagnostics retain this and the last sampled frame independently, even when execution ends at the frame budget. Counter differences are **not** silently reconciled or treated as parity.
3. **Generic parity comparator:** `RecompDevParity.exe --reference REF.json --candidate CANDIDATE.json` compares source/input identity and frame fingerprints; optional whole-run audio/state SHA-256 fields are compared where both available. New preview diagnostic ZIP emits an unqualified, video-only `candidate-capture.json` where native output contains a complete 64-bit fingerprint per host frame. No trusted emulator reference exists in this release, and the tool always prints `RECOMPDEV_GAMEPLAY_PARITY_QUALIFIED=FALSE` even on exact supplied matches. Input/audio/state **not captured in current preview**; parity remains BLOCKED.
4. **128-cycle bounded recovery:** `run/resume --max-cycles 1..128`, 2–3-digit immutable cycle paths, source-checked preview seed preflight, expanded bounded redacted upload ZIP exporter. Original stagnation policy and plugin DLL identity are unchanged. This is not zero-restart live recompilation; each cycle still builds/starts a new guest process.
