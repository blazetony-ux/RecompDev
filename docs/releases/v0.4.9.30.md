# v0.4.9.30 — Autonomous Native Recovery (incremental source implementation)

Status: **PARTIAL — UNQUALIFIED**. This source-only development update adds generic recovery-frontier lifecycle accounting, integrates it into the existing same-process `play` pipeline, and tests it. It is **not** evidence that Shinobi now continues through every translation gap.

## Implemented

- Generic immutable frontier identity: guest address, source physical offset and opaque machine mapping (no CPU-specific controller assumptions).
- Bounded request reservation; repeated identical gaps fail closed; different bank mappings or physical offsets remain distinct.
- Confirmation only after the guest's independently verified activation receipt.
- Explicit request logging and no premature "resuming" notice before activation acknowledgement.
- Nine new regression tests and the `v04930_recovery_frontier_contract` CTest registration.
- Correct `RecompDev.exe --version` reporting to v0.4.9.30.

## Existing facilities retained, not newly built

The v0.4.9.29 live launcher already owns same-process hot native translation, source verification, module compilation/activation, state fingerprinting, persistent native source history, and Git queueing. Those paths remain available through `RecompDev.exe play ROM` / `run ROM --auto-native`. The separate `preview` command remains a diagnostic/recovery path and should not be mistaken for same-process continuation.

## Outstanding acceptance

- Owner Windows compile and full regression CTests (95 registered expected).
- Live Shinobi demonstration: untranslated PC -> source-attested translation -> compiled module -> guest activation ACK -> same-process resumption and observable frame progress, without reset or guest interpreter fallback.
- Fantasy Zone regression; longer frame, input and scroll continuity; audio/video/hardware timing parity.
- Source-only promotion does not activate the installed native runtime.
