# v0.4.9.35 — Universal Offline ROM Interrogation (source candidate)

**Product direction:** Stop treating gameplay as the necessary path for discovering each executable address. Provide one ROM-input/analysis command and versioned evidence output across interchangeable CPU, machine and format provider combinations. This design is not game-specific, Z80-specific or Master System-specific. It implements the hardware-neutral product architecture mandated by [DEVELOPMENT-CONTRACT.md](../project/DEVELOPMENT-CONTRACT.md) and retains the [PREBUILD-v0.4.9.7.md](../project/PREBUILD-v0.4.9.7.md) preservation rules.

**Scope:** `git-main-only-no-runtime`, `infrastructure-source`, as required by the canonical installer. No runtime slot activation or game-source Git mutation. Owner acceptance: Windows MSVC, complete updated 102-test CTest suite, documentation and provenance checks, plus source-only functional confirmation on existing Shinobi ROM. Source promotion and export runtime qualification are distinct.

## Actual delivery

- One `RecompDev analyze --rom FILE --out DIR` command; `analyze --profiles` provides the versioned list. No launches or user gameplay required.
- Replaceable format detector, CPU/ISA decoder, and address-mapping provider registered by data, with stable v1 source/provenance reporting and no game-specific address tables in the controller or analysis engine.
- Three independently authored fixture profiles: Sega Master System/Z80 with bank mapping and source-bank inventory; Sega Mega Drive/Motorola 68000 cartridge/reset-vector with conservative static instruction subset; PS-X EXE/MIPS R3000A with payload load mapping and branch-delay-slot discovery. This is multi-format *static analysis*, not Sega Mega Drive/PS1 gameplay or complete game translation.
- Exact SHA-256 instruction/source/provider provenance, bounded CFG worklist and recorded unresolved reasons (indirect jump, unsupported opcode, unknown bank, unknown memory effects, budget), orphan-bank *hypotheses* that are not admitted executable code, invalid-ROM manifest status, and overwrite/source-mutation protection.
- Adds two new native-registered Windows CTests: Python 3-ISA/negative-unit contracts and direct compiled-controller three-ISA command dispatch. All prior 100 CTests remain required.

## BLOCKED acceptance (not silently waived)

Ghidra/P-code whole-bank translation, native generation of complete scanned code, automatic speculative code classification, semantics and gameplay correctness, 68000/Z80 dual-CPU coordination, PlayStation CD/BIOS/GTE support and all-console input/video/audio parity are **BLOCKED**. An arbitrary ROM cannot work until matching CPU, machine, format and hardware services exist and are independently qualified. Successful image recognition and static instruction-byte identification do not imply a playable binary. The v0.4.9.34 synthetic standalone exporter remains operational and unchanged but is not yet wired to these unqualified candidates.
