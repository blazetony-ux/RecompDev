# RecompDev v0.4.9.2 — independently versioned SMS sprite-video plugin

**Date:** 2026-11-05. **Release type:** Incremental targeted video plugin + source-only staging bridge. The original 642 historical files and generated translated game-code remain unchanged. The general-purpose controller and presentation host do not acquire SMS-specific logic.

## What changes

`rd_video_sms_mode4` 0.1.0 is a separate dynamic library with an opaque, versioned C ABI. It uses Master System VRAM, CRAM and VDP registers to compose the legacy-compatible Mode 4 background plus an actual sprite layer. Sprite processing includes SAT Y terminator `$D0` in 192-line mode, Y+1 placement, sprite palette bank 1, pattern bank R6, R0 early shift, R1 8x16 patterns/magnification, transparent zero, background priority only on nonzero tile pixels, front-to-back SAT ordering, a per-scanline eight-sprite limit and colliding-opaque-pixel diagnostics. Display timing, SMS1 magnification quirks and collision/status readback are still unqualified.

`sms_video_integration` 0.1.0 adapts an **external staged copy** of a source-attested generated game project to load the DLL at runtime using the `RECOMPDEV_SMS_MODE4_DLL` environment setting. It checks the ABI and fails closed if the plugin cannot be loaded. The launcher verifies the active component hash before setting the path and captures `sms-sprite-stats.csv`, separating SAT data absence from rendering omissions. Native app runtime build paths remain outside the source checkout. Neither the generic runtime host DLL nor the immutable legacy Master System renderer changes.

## Tests and acceptance

The new C++ contract test verifies SAT termination, transparent/opaque pixels, priority, sprite bank selection, early clock, 8x16 size, doubled sprites, overlapping sprite priority, scanline overflow and malformed buffers. Python tests verify immutable source and generated Z80 translation, idempotent staging and cache integrity. Native generated synthetic C++ compilation and execution exercises the dynamic plugin ABI.

**Still unproven on the owner's Windows PC:** first-level Shinobi player/enemy visibility, VDP pixel parity, continuous gameplay, ROM-independent game build. The next interactive run should inspect the CSV and screenshots; separate native code coverage blocker `0x1E62` remains open.

## Safe lifecycle

The Git checkout must be clean at `workspace/v0.4.9.1`. The installer validates SHA-256 baseline files, applies only changed source and docs, builds only `rd_video_sms_mode4` and its smoke executable, runs targeted and historical regression gates, preserves existing active DLL hashes, activates only the new video DLL, records a Git tag and creates external backups. Compiler artifacts, runtime DLL, recovery cache and evidence remain in their established sibling directories.
