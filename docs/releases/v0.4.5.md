# Workspace v0.4.5 — Documentation and governance

**Status:** Workspace snapshot; publish only after the updater passes acceptance checks. Prepared 2026-11-04.

## Scope

This update reorganises current project documentation into an indexed technical knowledge base and enforces docs/changelog gates in the existing local Git acceptance and workspace release process. It is a **documentation/tooling update**, not a native CPU, console, hardware or game-parity release.

## Changes

- Added root `README.md` and `CHANGELOG.md`; created architecture, component, project, development, recompilation, platform, research, history and release indexes.
- Preserved previous root-level migration notes, provenance JSON and validation JSON in categorised historical/release paths. Neither the frozen 581-file v0.4.0.45 tree nor frozen 61-file harness v0.3 tree was modified.
- Added per-component changelogs documenting initial inventory versions and true production/harness scope. Future component acceptance requires a new meaningful entry for that changed component only.
- Added `workspace_governance` component v0.1.0 and automated documentation validation; integrated it into plugin acceptance and formal workspace tags.
- Added transactional, SHA-verified small-update bootstrap with pre-commit source rollback and no full reinstall.

## Unchanged versions and binaries

Controller `0.4.4`; ten compiled harness DLLs `0.1.0` each; four preserved production adapters `0.4.0.45`. No C++ compiler invocation or binary activation is required for these documentation changes. Existing evidence, owner catalogue and all previous source commits are retained.

## Validation

The update procedure checks exact prior Git commit and file hashes, docs/link/changelog rules, original 642 historical source bytes and the existing 38 CTest regressions **without recompiling C++**. The apply report and updated Git bundle are recorded under `RecompDev-Archive`. Windows installation and post-update results must be confirmed from the owner's machine; Linux test results alone do not establish Windows parity.

## Known limitation and next milestone

The production Shinobi/Ghidra/continuous recovery services remain preserved Python adapter implementations. The ten interchangeable C++ DLLs operate in the harness, not yet in that production recovery path. Next: prove a swappable, versioned CPU/translator bridge on authenticated real instructions without modifying the frozen legacy engine.
