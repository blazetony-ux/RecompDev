# RecompDev v0.4.9.3 — native movement correctness diagnostics

**Date:** 2026-11-05. **Release type:** Incremental source-only diagnosis. This is NOT a claimed movement-direction correction and does not recover the separate untranslated instruction at `0x1E09`.

## Purpose and evidence

The previous Shinobi interactive run reached 1,125 native frames, captured long normal directional holds and ended at untranslated `0x1E09`. The user reported that movement initially felt correct but later appeared to change direction. The last evidence records the **host-level** button transitions, but not the exact DC/DD values read by translated guest instructions or corresponding raw per-frame sprite coordinates. Reversing keyboard mappings without those observations would risk hiding a Z80/VDP or guest-state error.

## Implementation

`movement_trace` v0.1.0 adds a strict, source-verified staging adapter. It instruments only the copied generated native frontend (`live_sms.hpp`) and copied machine bus (`runtime.cpp`), plus a replaceable header-only neutral CSV recorder. It does not alter `translated.cpp`, the original production translator, the ROM or any active shared library. The generic runtime launcher accepts `--movement-trace`, and PowerShell `Run-Native-Game.ps1` accepts `-MovementTrace`.

When opted in, new files in the standard ZIP are:

- `movement-controller.csv`: cycle-stamped logical button transitions and active-low guest controller byte values.
- `movement-port-reads.csv`: actual I/O read cycle, PC, port and result for SMS 0xDC and 0xDD.
- `movement-frames.csv`: unique render sequence, guest frame/cycle, VDP registers 0, 1, 8, 9, SAT base and raw entry count.
- `movement-sprites.csv`: per-frame raw SAT index, X/Y, pattern and computed screen positions, with no invented player identity.
- `movement-diagnostics.json`: controller-mapping mismatches, port-read comparisons, scroll-register changes and input-direction segments. Zero controller reads are reported as insufficient evidence.

Every filename is bounded and written only to external evidence. Captures may impose additional runtime overhead; comparisons should use guest cycles, not wall time. Captured raw coordinates are not reference-qualified Master System VDP or gameplay world coordinates. The native emulator's approximate timing also remains unqualified.

## Windows acceptance

Install on clean `workspace/v0.4.9.2`, verify the new `workspace/v0.4.9.3` tag, and launch the **latest recovered round-03** project with `-MovementTrace`. During live play try short Left / release / Right / release sequences, then normal jump/attack, and upload the resulting evidence ZIP. If the guest bytes/reads stay correct while the visible character travels the wrong way, investigate guest logic, scroll and sprite positioning rather than remapping the keyboard. If controller or readback mismatches appear, locate the earliest cycle and PC before changing machine behavior.
