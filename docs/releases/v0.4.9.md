# Workspace v0.4.9 — Input-driven native recovery

**Type:** Incremental, source-only production tooling update. **Date:** 2026-11-05. **New component:** `input_recovery` v0.1.0. No existing binary component version changes.

## Implemented

1. Exact guest-cycle input transition logging in a disposable compiled native game's frontend, using the same abstract button masks as the generic runtime host. The verified generated game instruction code (`translated.cpp`) and preserved legacy source stay unchanged.
2. Input replay from previous run evidence, with ROM SHA-256 identity checks and strict bounded parsing. Prefer `guest-input-cycles.csv`; convert older millisecond-only logs with an explicit guest clock, prominently marking them estimated and potentially non-reproducible.
3. Automatic bounded replay against the previously generated application to confirm the same stop kind, PC and approximate frame count before running source-attested recovery. No progression or correctness claim is made for a divergent replay.
4. Recovery through the **preserved** generator, Ghidra/preparation and reset-replay engine with the replay fixture, verified history and bounded recovery rounds. It generates a new game application without rebuilding the compiled controller, Z80 DLL, runtime DLL or other components.
5. Separate `tools/Recover-Native-Input.ps1` command and automatic, versioned diagnostic ZIP containing replay, validation results, recovery outcomes and logs. Existing `tools/Run-Native-Game.ps1` can still run interactively or use a replay in headless mode.

## Verification scope

The initial implementation has synthetic guest input and source-integrity tests and existing workspace regressions. It has **not** yet been validated on the owner's Windows system or proved capable of reaching Shinobi's playable level. The v0.4.8 button-1/Z run reached frame 201, then stopped at untranslated physical address `0x7BE8`. That run's wall-time recording will be treated as an *estimated* input replay; a deterministic guest-cycle recapture may be necessary before source recovery can be attempted safely.

## Limitations

No per-function compilation guarantee, live hot-patching, ROM-free game build, independently verified sound or game correctness. The native app continues to load the original owner ROM. The Master System clock setting belongs to the current console launcher, **not** the generic replay format or host. No game-name-specific behaviour is embedded in the recovery logic. The original 642-file source preservation gate remains mandatory.
