## Source changes

1. **Non-blocking native monitor UI:** WinSock reader thread fills bounded 8192-event queue, Windows UI consumes at most 768 records on a 100-ms timer. An incremental line editor avoids expensive rebuilds; history capped at 2,000 entries, visible lines at ~1,800. Read-only UI has case-insensitive text/PC/physical-address/opcode-class/event-type searching, inclusive address ranges, matched-only filtering, next/previous and follow-latest controls. Stop PC is identified as terminal, not conflated with last sampled SP/steps. No Python/Tk GUI fallback.
2. **Source-correct capture:** `RecompDev.exe preview --job JOB --cycle N --monitor-pc 0x0BDB --monitor-pc-range 0x0BD8:0x0BE4 --monitor-matched-only`. The first two flags can repeat (max 16 each). Controller validates uint32 addresses, range order, CPU-neutral semantics. Preview transports configuration in private native environment, captures every address hit before ordinary sampling, and emits a bounded `watch_hit` indicator and cumulative watch-hit count. Native publisher still limits total events to 200,000 and full JSONL trace stays local; diagnostic ZIP keeps a recent 5,000-event excerpt. This is observation, not pausing, stepping or breakpoints.
3. **Display overflow audit:** Controller diagnostics broker emits cumulative per-subscriber overflow notices; GUI discloses separate broker queue losses, local display queue drops and rejected events. These affect only presentation; they do not alter native game execution or prove full trace archival.
4. **Other ROMs:** `tools/Run-RecompDev-ROM-Smoke.ps1 -Controller EXE -RomDirectory DIR` runs each `.sms` (excluding Shinobi by default) as a separate bounded job, preserving original ROMs and all existing evidence. CSV report includes SHA-256, job, frame count, status and diagnostic path. The script has conservative 1 cycle/1 round/120 frames/120-second/2.5M-step defaults. It is not a gameplay-parity certification.

## Windows stress-test correction (candidate revision)

The first self-contained Windows validation passed **73/74** CTests but
`v04922_native_monitor_stress` terminated with `0xC0000409`. The stress test
attempted to unlink a temporary telemetry file before the static C++ publisher
released its open output stream. Unix permits unlinking open files; Windows
normally denies it. The provider-neutral publisher now supports an explicit,
idempotent `finish()` that flushes and closes the trace before test inspection
and deletion. This also makes file finalization lifecycle explicit to consumers.

The test now also prints a specific failure reason on unexpected C++ exceptions.
This correction changes the test and common telemetry publisher only; native
CPU, machine, renderer, plugin ABI and guest execution are not changed. Local
Linux focused stress regression passes; the entire owner Windows acceptance
suite and live Win32 UI acceptance must be rerun before promotion. Rizin
`ESC[2K\r` array framing (COMPAT-023) is **not fixed in v0.4.9.22** and is
tracked for the next increment.

## Acceptance and restrictions

**Owner baseline:** v0.4.9.21 Windows full 72/72 and all 642 originals preserved; actual owner Shinobi native preview reached 1,800 host frames, but the monitor seemed nonresponsive during execution. Native process exit code zero did not prove gameplay correctness. The new monitor needs owner Win32 GUI stress and focus tests; **Windows validation/promotion are not claimed until logs confirm them**.

**BLOCKED:** real non-neutral game input, deterministic reference-emulator video/audio/CPU/RAM/VDP/mapper/IRQ parity, second ROM validated compiled output, complete native multi-ISA and analysis ABI, all legacy source parity and no-Python orchestration. Source-only Git checkpoint/promotion never replaces active runtime, frozen history, or original evidence. The installer and Git rollback gates remain unchanged. Preserve 642 historical files byte-for-byte.
