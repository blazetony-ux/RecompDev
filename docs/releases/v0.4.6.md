# Workspace v0.4.6 — Production CPU plugin integration, phase 1

**Release date:** 2026-11-04. **Classification:** Coordinated one-time source/API migration with an incremental Z80 DLL build; not a full workspace reinstall. Windows validation is required after deployment.

## Implemented

- Extended the independently versioned `rd_cpu_z80` DLL with `rd_z80_source_gate_v1`, a stable C ABI for Z80 source-instruction admission. It validates well-defined opcode instruction lengths from actual source bytes and reports prefixed instruction lengths that require fuller decoding rather than falsely asserting completion.
- Added `production_cpu_bridge` v0.1.0. The preserved Ghidra/source verifier is still authoritative for ROM hashes, physical bank mapping and source instruction hashes. The bridge calls the *installed active* Z80 plugin on every unique attested physical instruction before starting the preserved native recovery engine.
- The bridge verifies the active DLL SHA-256 and version-store file against the runtime lock, reports selected version/hash, admission counts and opcode families, refuses corrupt/invalid/rejecting plugins, and writes `production-cpu-gate.json` into centralised per-run evidence. Provenance includes the selected gate details.
- `--cpu-plugin auto` uses the selected plugin when it has the new ABI; a v0.1.0 or missing plugin gets an explicitly reported backward-compatible legacy fallback. `--cpu-plugin required` demands the new gate; `--cpu-plugin legacy` explicitly opts out. A corrupt or rejecting new DLL **never** silently falls back.
- Updated the documentation index, handover and project roadmap, and added dedicated component changelog entries. The pre-existing compiled controller remains v0.4.4 because its binary is unchanged; only the edited Z80 DLL is recompiled.

## Validation and boundaries

The Linux source tests verify original authenticated synthetic ROM/P-code instructions, native ABI invocation and length checking, a deliberately rejecting native replacement, SHA-256 tampering, controlled fallback, and full legacy native-compilation entry after a successful gate. Historical source integrity remains a mandatory gate. CTest regressions and Windows execution must still be checked on the owner's machine.

**Not implemented:** substitution of native CPU instruction execution, machine-hardware APIs or the legacy Ghidra/P-code compiler with these DLLs. This patch proves the first mandatory production boundary; subsequent phases must migrate actual translation and hardware execution independently. Do not infer Shinobi parity, PlayStation support or Mega Drive hardware functionality from it.

## Changed component versions

- `rd_cpu_z80`: 0.1.0 → **0.2.0** (DLL rebuilt)
- `production_cpu_bridge`: **0.1.0** (new source-only component)
- `workspace_governance`: 0.1.0 → **0.1.1** (tooling source/acceptance boundaries)
- Controller, all other compiled plugins and four frozen legacy services: **unchanged**.
