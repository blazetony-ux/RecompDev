# Workspace v0.4.7 — Preserved production translation and Workbench viewer

**Release date:** 2026-11-04. **Type:** Two new independently versioned Python source components, no compiled controller or DLL replacement.

## Implemented

- `production_translation` 0.1.0 provides a SHA-256-pinned, selectable production adapter to the **full preserved** v0.4.0.45 native P-code generator. A dedicated subprocess injects only the generator callable and invokes the exact preserved continuous-recovery runner. Every recovery round now emits a provider witness with original generator source identity and invocation count. Explicit `RECOMPDEV_TRANSLATOR_MODE=legacy-direct` runs the unmodified entrypoint.
- `workbench` 0.1.0 runs independently as a loopback-only, token-protected SQLite browser. It reads the existing owner catalogue in SQLite read-only mode, escaping values, paginating queries and forbidding write requests. It logs only under the external version-derived `RecompDev-Evidence/v0.4.7/workbench` directory. Normal recovery evidence now also selects its version directory from the workspace manifest instead of a hardcoded previous release.
- Documentation, meaningful changelogs and a reproducible real-ROM qualification plan are maintained under `docs/`.

## Validations and honesty requirements

The provider must produce **byte-identical native-project files** for the authenticated synthetic test export and execute bounded native code through the original recovery path. The Workbench unit suite must assert read-only database identity across multiple requests. Existing 38 CTest regressions and 642-file preservation checks must pass, and Git/runtime hashes must remain unchanged except for the documented source update.

**Still unverified:** the claimed earlier 600-frame Shinobi result has not been independently reproduced under the current Git workspace; it is a regression target, not a pass claim. Frame budget completion is not correctness or ROM independence. Video, audio and hardware parity remain unqualified. The Z80 DLL is still an admission gate, not the native instruction generator.

## User workflow

Apply the small Git patch from the previous `workspace/v0.4.6` baseline. Launch Workbench with `tools/Start-Workbench.ps1`. The existing `RecompDev.exe` ROM recovery command does not change; it will use the hash-pinned preserved-code provider by default. No C++ rebuild is required.
