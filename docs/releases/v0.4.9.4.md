# RecompDev v0.4.9.4 — generic guest-state diagnostics

**Date:** 2026-11-05. **Release type:** incremental source-only diagnostics, NOT a gameplay or input-direction fix.

## Motivation

The latest 2,400-frame Shinobi test shows 2,091 correct controller-port reads, but guest movement appears to stop or behave oddly during parts of the first level. The existing renderer/port trace cannot tell whether the underlying game RAM state is moving or whether rendering/collision is responsible. Adding a direct Shinobi work-RAM scanner to the generic runtime host would violate the project's interchangeable-plugin architecture.

## Architecture

`state_observer` 0.1.0 is an independent diagnostics contract: read-only guest memory regions are described by a machine provider (ID, guest address space, base, span, endianness and clock domain) and sampled at host-defined guest time points. No game/CPU/console semantics live in the recorder or generic memory analyzer. `movement_trace` 0.2.0 contributes the first machine adapter (SMS 8 KiB work RAM). New MD/PS1 providers may declare their own memory windows and clock domains without changing the shared analyzer. Inputs are correlated ONLY when the adapter declares the same clock domain. Raw bytes are recorded as bounded changes, not a full RAM dump on every frame.

## Evidence

`Run-Native-Game.ps1 -MovementTrace` captures the existing controller, port, scroll and SAT traces unchanged plus `state-memory-regions.csv`, `state-memory-deltas.csv`, `state-memory-summary.csv`, and `state-memory-diagnostics.json`. An additive pointer is included in `movement-diagnostics.json` / the runtime report. A truncated trace is explicit. Candidate offsets are not labeled Shinobi player coordinates, collision flags or world X/Y, and do not prove gameplay parity.

## Preservation and risk

The v0.4.9.3 source checkout is the exact expected Git baseline. Only source and docs for the diagnostics adapter and staging launcher are modified. The old translator, `translated.cpp`, console plugins, controller, runtime-host binary, SMS video DLL, original ROM and all protected 642 files stay unchanged. The updater checks baseline hashes, compiled C++ and focused tests, source protection, binary locks, then commits and creates a Git bundle.

## Validation scope

Compiled cross-platform multi-region/multi-clock observer and SMS provider smoke; original movement tests; synthetic delta-schema validation. Windows owner installation, Shinobi movement diagnosis, and independent reference-emulator agreement remain **NOT ESTABLISHED**. This release is observational, not a game-logic fix.
