## Actual implementation

- Compiled controller `RecompDev.exe`: `preview --job ID --frames N --steps N --video window --input live --auto-recover` dispatches an unmodified preview, reads a separately SHA-identified result receipt, requires a source-attested untranslated-code ZIP containing exact guest-cycle input, and independently runs existing preview evidence preflight before scheduling a recovery job. By default `preview` remains read-only. Reject `--hold-window` with `--auto-recover` to avoid a misleading frozen window.
- Automatic recovery **forks** a child job using the last source-matched immutable previous orchestration session; previous completed job remains untouched and the new job's frame target respects the live preview's requested budget. The verified original job identity travels with the handoff. This specifically addresses frame-budget-complete neutral runs not admitting a new input-driven missing code path.
- Existing `execution_monitor` diagnostics now produce a bounded, typed `guest-input-cycles.csv` plus exact SHA in ZIP manifest; source and target are rechecked, and capture truncation prevents automatic replay. The compatibility analysis provider replays those exact guest-cycle button transitions in native execution instead of neutral input. This can re-run from a fresh start; it does not pretend a full guest state checkpoint exists.
- Content-addressed artifacts may now include complete partitioned native **generated source** files and replay evidence. No compiled game-code DLL cache or hot-replaceable native blocks are shipped.
- Existing Z80 instruction and SMS hardware plugins, other CPU formats, historical 642 source files and v25 evidence records remain untouched by this source patch. No title-specific production paths.

## Acceptance / BLOCKED

**Actual Windows live Shinobi result (owner):** In the Validate-only build (`20261108T173446Z-5976`), Windows MSVC and 82/82 CTests passed, as did all 642 protected historical-file checks. Live `Z` input reached `UNTRANSLATED_INITIAL_CODE` at guest address `0x052A` (331 host frames), but automatic recovery preflight failed **before** creating a recovery child job. Source root cause: `diagnostic_zip()` includes `candidate-capture.json` when video fingerprints are available, while `verify_and_stage_preview()` previously rejected that known optional member. This package amends the verifier to admit the exact six-file combination with SHA-verified manifest and source-bound capture; future errors emit a sanitized error code. Full Windows revalidation plus real recovery beyond `0x052A` remain BLOCKED. The earlier 82/82 result does not qualify live recovery.

**Windows candidate revalidation required:** Owner validation of the first v0.4.9.26 source ZIP built all MSVC binaries and verified 642 historical files, but failed `v04919_controller_preview_native` (81/82 CTests) because two legacy Python fixture callers lacked the newly optional `result_json` parameter. The corrected ZIP has one functional code change: the preview receipt presence check to `getattr(opts, "result_json", "")`; the five legacy preview cases now pass in Linux locally. The revised package has a new SHA-256 and must be validated from scratch on Windows. Neither source nor runtime has been installed.

**Linux source-level:** compiled `RecompDev` and controller, registry and artifact contracts; targeted CTests include automatic previous completed-job recovery into an immutable child, absent-replay refusal, exact source-binding, old evidence unchanged, artifact-store and provider replay, and Python malformed/cross-source input rejection. These tests are synthetic; they are not a real game run.

**BLOCKED:** Owner Windows full `ctest -C Release`, 642 original-file integrity, installed-source/binary/plugin hash audit, correct Ghidra and Rizin provider location, Shinobi `Z` press beyond physical code `0x052A` toward 2,400 host frames, second-ROM proof, independent CPU/video/audio/hardware parity, automatic reopening of interactive live game after a replayed recovered translation, compiled-game DLL reuse and generic multi-ISA autonomous recovery. No completed native gameplay, title-screen responsiveness or self-contained game claims.

**Failure policy:** If no attested replay exists, the source changes, the ZIP hash/member changes or the analyzer encounters unsupported semantics, the controller stops with explicit failed reason. Do not mark frame-budget-only recovery as parity or install this candidate into active runtime.
