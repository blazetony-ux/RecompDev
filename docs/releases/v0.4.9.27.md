### Implementation

1. **Delta-native recovery ABI:** The translation plugin accepts a source-verified exclusion coverage manifest of previously compiled guest physical offsets, guest PC/length and instruction-byte hashes. Only missing instructions produce new native C++ and DLL entry points; the existing generic multi-module loader dispatches across them. CPU and mapper checks remain in the owning providers, not the controller.
2. **Verified immediate retention:** Each successful hot-loaded DLL is acknowledged by the still-running guest process through an immutable source/activation-bound receipt. The controller commits its compiled DLL, generated source, translation manifest and SHA-256 digests atomically to the per-game cache *as soon as acknowledged*, not only after frame-budget success. Crash or early exit does not discard confirmed modules.
3. **Generated-source history:** The ROM-SHA-scoped Git history retains generated native C++ and source-discovery attestations, manifest and exact compatibility fingerprint, without ROM data or DLL binaries. A separate immutable artifact store holds compiled binaries. Source Git checkpoints occur after every four acknowledgements and at normal session conclusion; the underlying generated source itself is saved immediately. Generated-history commits are local, not remote pushes, and do not modify the canonical `RecompDev` Git repository.
4. **Consolidation:** After a normal session, the controller uses retained exact source-bound discovery records to regenerate the cumulative native translation once, compiles one consolidated game DLL, verifies that it covers every acknowledged instruction, records its generated-source Git commit and publishes an atomic SHA-verified current-library pointer. Next launch preloads the compatible consolidated DLL and resumes compiling only remaining code. This is **source regeneration + one native build**, not a proven object-only relink. It is optional/offline and cannot gate guest execution.
5. **Interruption and input:** On guest closure during a native compile, terminate its compilation process tree rather than leave an orphan linker. Keep activation-acknowledged modules safe even if consolidation cannot complete. Carry keyboard press edges across compilation pauses; rendering responsiveness, input fidelity and Windows game behaviour still require owner acceptance.

## Implemented in this completion candidate

The prior v0.4.9.27 *native hot-module foundation* remains in place: generic `RD_NativeBlockV1`, verified independent DLL loading, same-guest state continuity, backwards-compatible self-contained previews. The following elements are newly integrated:

- `RecompDev play ROM --frames 2400` and `run ROM --auto-native` automatically locate the *matching validated transaction source stage* or use the established runtime source pointer, and run one controller-supervised session. An attempted Windows Win32 monitor starts before initial analysis, and a native game display starts as soon as the first verified C++ translation compiles.
- Running native game state sends a source-bound, SHA-verified, immutable `request-NNNN.json` for a genuine untranslated code frontier. While it waits, the game event loop continues pumping the same host/window. The controller verifies ROM/mapper/physical PC and request, runs Ghidra observed-bank analysis, performs **module-only native translation/compilation**, stages the binary with SHA-verified source/ABI identities, and returns an immutable `response-NNNN.json`. The original native guest object resumes with unchanged guest-state fingerprint; no process restart or input replay.
- Machine-neutral host/module-activation code is separate from SMS/Z80 source-discovery analysis. The Z80 CPU plugin owns newly implemented live-register `JP (HL)` source semantics so indirect control flow no longer requires guessing static branch targets or game-specific patches. Unsupported control-flow variants remain fail-closed.
- A persistent compiled-module cache is keyed to exact controller/CPU/translator/machine binary hashes, native ABI header digest, host architecture, ROM SHA, *observed* guest PC/physical address and mapper. Entries are immutable, SHA-checked and committed only after same-process activation counts and successful frame target. Compatible second sessions reuse them without recompiling, while the native loader again validates source SHA/ABI/instructions. This is **not** cross-ROM compiled-code reuse or a substitute for shared CPU instruction semantics.
- New `v04927_controller_autonomous_two_hot_recoveries` CTest uses a previously unseen **synthetic** ROM, forces two distinct live code gaps, verifies the same game process resumes and frames advance, then relaunches to check compiled cache MISS→HIT and zero subsequent recovery compiles.
