## Verified observation and implementation

The owner v0.4.9.19 actual Windows preview of Shinobi stopped **without pressing Z** at PC and physical ROM offset `0xADAF`, with native status `UNTRANSLATED_INITIAL_CODE`, native 936 host video frames and sampled guest VDP frame 934. It was a controlled guest execution stop, not proof of a Windows crash. We do not assert these counters have identical semantics.

- `execution_monitor/job_preview.py` records a `GUEST_BLOCKED_UNTRANSLATED` result, a clear display status, distinct guest/host frame counters, and ROM-free `recovery-seed.json` only if the complete native final mapper/PC/SP/physical state passes independent ROM mapping checks and matches the published native stop. Existing preview behaviour remains entirely read-only.
- The compiled controller accepts **explicit opt-in** `resume --job JOB_ID --max-cycles NEW_LIMIT --preview-stop ZIP`. A no-write `preview-verify` subprocess rejects forged or incomplete ZIPs before job status changes. The analyzer rechecks session, previous translated source, ROM hash, mapper, and observed PC before importing the stop as an immutable history record; the native discovery DLL rechecks source address mapping. No Shinobi-specific addresses or platform-dependent GUI decisions exist in the controller.
- The imported preview stop becomes part of the next session's cumulative history with provenance, so subsequent bounded cycles can reuse it without re-reading the original ZIP. Repeated evidence is deduplicated, not considered new coverage or gameplay progress.
- The v0.4.9.19 preview ZIP lacks observed native mapper/SP fields, so it cannot meet this contract. A new v0.4.9.20 preview must be captured before an opt-in recovery handoff. Never reconstruct the missing mapper by guessing.

## Existing-job provider boundary

A recovery job pins the exact original compiled provider directory. The new controller will deliberately reject a `resume` of a job created with another transaction's DLL directory (`JOB_PLUGIN_DIR_MISMATCH`) rather than silently switch processor/machine/translation DLLs. To exercise the opt-in preview handoff, first create a **new v0.4.9.20 job** with the current v0.4.9.20 candidate executable and `--import-history` pointing to the original v0.4.9.18 `cycle-04` evidence. The original 936-frame job remains immutable. Then preview and resume that **new** v0.4.9.20 job using the same executable, with an archive generated from its newest cycle. Existing v0.4.9.19 preview ZIPs cannot supply a verified seed. This does not imply ROM execution has been validated on Windows.
