# v0.4.9.32 — Live native audio output and auditable PCM

**Status: Source-only candidate. Audio/playability parity BLOCKED pending real Win32 and independent reference acceptance.**

## Corrective gameplay change

Real Shinobi evidence `live-20261111T181322Z-dac4f1dc-25140` demonstrates guest native activation at PC `0x1F9A` and continuation through frame 2,396; the game was deliberately launched with `--audio null`, therefore it could not produce audible sound. The actual native game's existing `speaker` and `capture` backends are already implemented. The live launch adapter now selects **speaker** by default for owner-visible play instead of hardcoding **null**.

- `RecompDev.exe play "C:\Roms\MASTERSYSTEM\Shinobi (USA, Europe, Brazil) (En) (Rev 1).sms" --frames 2400 --max-recoveries 128` requests live speaker output.
- Add `--audio capture` when no speaker is available; this generates a WAV in the native game evidence directory.
- Add `--audio null` only when intentionally discarding audio.
- The session report records selected audio backend, PCM total/nonzero sample counts and SHA-256 of a retained WAV when samples were emitted. A missing/mismatched output is an explicit failure, not an invented successful audio verdict. Synthetic tests default to capture to avoid devices.
- This is native **audio output routing** through existing hardware plugins, not a new PSG emulation implementation. Nonzero PCM does not prove correct music, timing, volume, or hardware parity.
