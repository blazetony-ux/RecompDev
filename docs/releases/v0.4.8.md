# RecompDev workspace v0.4.8 — Generic interactive native presentation host

**Release date:** 2026-11-05. **Type:** Independently versioned `rd_runtime_host` v0.1.0 native DLL plus source-only generated-project launcher. This is a new component; the controller and previous compiled plugin versions remain unchanged.

## Delivered

- Public C ABI for CPU- and machine-neutral BGRA8888 framebuffer, interleaved PCM16 audio (1–8 channels; initial Windows speaker mixes to mono), abstract button states and lifecycle. Windows window and WaveOut backends reuse *the existing preserved* Win32 implementation without modifying its historical sources; portable headless backend works with the same exported functions.
- Dedicated CMake build target `rd_runtime_host` and test executable `rd_runtime_host_smoke`. Runtime binaries and generated native app builds are outside Git. Existing ten DLLs and compiled controller are not rebuilt by the update.
- Optional standalone native project launcher which locates the previously generated native C++ project, verifies that it matches the owner's ROM, stages only source files in the external cache, patches only presentation adapters, compiles the generated native application incrementally, and runs its real native code with a window or in headless mode. Execution reports, abstract input-transition logs and upload-ready ZIPs go to `RecompDev-Evidence/v0.4.8/runtime-host/`.

## Verification and explicit gaps

Synthetic source-attested compiled native application execution, library ABI smoke, wrong-ROM blocking and source preservation are acceptance gates. **The prior Shinobi 600-frame execution is a separately established legacy production result; interactive native playback and user input still require a real Windows run.** Neither 600 frames nor a native window proves valid game mechanics, full sound, independent hardware parity, or ROM-free packaged games. The generated application currently loads the original ROM at startup and is not standalone without it.

The default Windows launcher uses `--audio null` because Shinobi's last verified PCM capture was silent; sound can be enabled separately. This release is a reusable **presentation boundary**, not an entire cross-console execution migration. Workbench and the legacy translator remain untouched.
