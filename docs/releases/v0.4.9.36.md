## Implemented engineering change

- A generic **bounded call/return and abstract-register facts engine**, with immutable known constants tracked under CPU-provider-owned register names. ISA-specific effects and indirect-target resolution remain in interchangeable Z80, Motorola 68000 and MIPS R3000A providers. The machine provider solely owns physical address mapping, mapper-register effects and source-bank inventory. Source format recognition remains a separate plugin.
- Z80: tracked BC/DE/HL/IX/IY, A and SP constants where safely modelled, indirect JP (HL/IX/IY), memory writes through known registers, stack push/pop and bounded return contexts. Unknown writes can invalidate mapper state. Unmodelled register writes conservatively clear facts. No assumption that a 256 KiB ROM is all code.
- M68000: conservative LEA absolute-long known address and JMP/JSR via An; known MOVEQ; bounded RTS pairing; unknown variable-length instructions still fail closed.
- MIPS: LUI, ORI, ADDIU and selected constant operations; bounded register-target JR/JALR, JAL/JR $ra pairing and ordered branch-delay-slot effects. Targets are read before the delay slot and slot effects precede successor execution. No PS1 BIOS/GTE/disc-image support.
- A **new explicit speculation boundary**: call-continuation hypotheses that cannot be statically justified retain `SPECULATIVE_CALL_CONTINUATION_NOT_REACHABILITY_PROOF` classification, and are counted separately. The analyser does not elevate a candidate to semantically verified or native compile ready. It reports resolved return/indirect sites and context budgets. This intentionally can reduce apparent static candidate counts compared to v35.
- The generic compiled-controller `analyze --rom ... --out ...` command, versioned output schema and unknown-format handling remain the same. Provider abstract-state contract increments to `ANALYSIS_ABI=2` and rejects old mismatched plugins; the native C ABI is not changed.

## Owner acceptance gates

1. Full 104 Windows CTests, including 16 new independent cross-ISA authored fixture tests and compiled-controller three-system abstract-resolution dispatch; existing 102 suites must still pass.
2. Source-only real Shinobi smoke analysis: no gameplay launch, correct SHA-256, all-bank inventory, explicit unknowns, and a truthful unresolved/supported instruction report. A reduced candidate count is **not** a failure if it reflects removal of speculative reachability.
3. Documentation governance, 642 byte-identical frozen historical files, signed-off canonical Git release transaction and rollback bundle. Generated-source plugin Git and active runtime must remain unchanged.

## Still blocked

No proof of whole-ROM executable code coverage, accurate CPU flags/value tracking, complete instruction-length decoding, indirect jump tables, decompression/overlays, control-flow graph reachability, native-source generation from this scan, standalone commercial game output, multi-CPU scheduling or independent hardware/gameplay parity. An arbitrary ROM continues to need matching format, CPU, machine and runtime plugins. No third-party ROM is included in the release package.
