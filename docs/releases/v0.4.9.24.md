## Functional change

- Native C++ `recovery_registry` component, CPU-neutral and ROM-SHA-keyed, retains immutable provenance-backed references to source-attested recovery sessions outside Git. `run --rom FILE` automatically reuses the strongest available same-ROM translation history, searching earlier versioned Evidence folders on first use. This avoids routine manual `--import-history`, but compiled binaries may still be regenerated and game execution still starts from its reset state. `cache --rom FILE` inspects eligibility without creating jobs; explicit `--import-history` takes precedence and `--no-auto-history` disables lookup. Index tampering, cross-ROM mismatch and path escapes are rejected, never treated as executable code. Existing independent provider verification remains mandatory.
- RUNTIME-004: bounded parser for exactly one unique valid terminal `NATIVE_APP_RESULT` in stdout logs beyond 512-KiB diagnostic threshold up to 16-MiB hard cap. Explicit `native_stdout_bytes`, diagnostic-oversize status and validation scope are recorded; duplications, bad JSON/schema, missing record, invalid counters or nonzero exit remain errors. Does not truncate logs or claim gameplay correctness.
- Two extra native/Python CTests target **78 total** and extend existing controller mock to assert automated history discovery without manual file input. Preserved source hierarchy unchanged, original `legacy/` and `baselines/` immutable. The Git-managed bootstrap installer remains embedded as a pinned release manifest member.
