## Delivered infrastructure

- Compiled controller `configure --workspace DIR` persists jobs outside AppData by default, with configuration and legacy pre-v0.4.9.17 job lookup retained. The default workspace is a sibling of the selected source checkout (the owner should explicitly configure an absolute workspace on staged validation binaries).
- Compiled `diagnostics export --job ID` and automatically invoked per-terminal-job diagnostic ZIP. A bounded maintained Python service exports sanitised copies of job/event/session JSON, checksums, human summary and manifest; no original ROM, raw Ghidra export, source binaries or SQLite data. Before sharing, users should still review the ZIP. Job data and original source-attested reports are never modified.
- Read-only local SQLite catalogue table counts/hash inventory. A 14-subsystem registry has accountable owners, current migration states and exit criteria; no blanket legacy parity assertions.
- Installer's explicit source-only promotion branch updates Git `main` and release tag after named mandatory tests, while leaving production runtime EXE/DLL and lockfile unchanged. Rollback and offline Git bundle backup remain. `Validate` creates a `dev/v0.4.9.17` checkpoint but does not install or push to GitHub.

## Windows acceptance and blockers

- Full Windows MSVC + CTest, original 642-file historical preservation, dev checkpoint and source-only `Install` transaction are required before reporting promotion success.
- A separately qualified runtime release still requires **Shinobi 1,800 frames** with independent gameplay input, VDP scrolling, PSG audio, IRQ/cycles/mapper comparisons; a second unrelated real ROM, native CPU/machine portability, ROM-free dependency closure, and compiled analysis ABI remain **BLOCKED**. Latest owner Shinobi result was 896 frames; no gameplay parity claim.
- Maintained Python analysis and diagnostic adapters, old campaign scheduling, asset export, and full old test suite migration are incomplete and remain tracked.

No special cases for Shinobi or Master System are added in controller job or evidence services. Read-only Workbench and old source remain preserved.
