# Workspace v0.4.9.1 — Recovery build-path correction

**Date:** 2026-11-05. **Type:** Targeted, source-only Git workspace patch. **Component changes:** `input_recovery` 0.1.1, `production_translation` 0.1.1, `workspace_governance` 0.1.2. The compiled controller and every runtime DLL retain their original versions and SHA-256 identities.

## Observed Windows failure and implemented correction

The original v0.4.9 input replay matched the guest stop at frame 201 and `0x7BE8`, then the native recovery compiler returned `BUILD_FAILED` with MSBuild error `MSB6003` while generating an internal CMakeScratch project under a very long evidence directory. This is consistent with a path-depth failure, but the exact OS-level cause is not independently proven.

CMake compiler intermediates now reside in `RecompDev-Build/native/<source-path-hash>`, outside Git and outside the evidence root. Full configure and build logs are recorded in each generated project's evidence, and the two final native executables are copied into the generated-project compatibility path required by the untouched historical session launcher. A build failure does not publish stale executables or run postflight. Versioned evidence and its ZIP continue to live in the external evidence root.

The production adapter now removes the legacy `--no-history-import` flag only if an explicit `--history-root` was supplied. The preserved `VerifiedCoverageCache` reattests every imported export against ROM SHA-256, target identity and source instruction bytes; there is no unverified translation fallback. The prior 600-frame run's owner-local historical recovery documents can therefore seed this run's isolated cache without modifying the production catalogue.

## Validation and limits

Focused tests cover deep-path native compilation and log retention, one-time history import, build failure suppression, replay stop integrity, original translated-code hashes and the old source preservation inventory. The existing C++ regression suite must pass unchanged; no full RecompDev rebuild is needed. Windows deployment and actual progression beyond Shinobi's `0x7BE8` remain to be checked on the owner machine. ROM-independent gameplay, PSG audio parity and control-response parity are not established.
