# v0.4.9.38 — universal offline ISA semantics and source-attested native register execution

**Release type:** source-only `infrastructure-source`, `git-main-only-no-runtime`. **Exact expected installed baseline:** `workspace/v0.4.9.37` Git `251f0210f74df1599ca3281ba977179d097553d1` (owner Windows 108/108 CTests, 642 frozen historical originals unchanged, generated-source repository published). This candidate must run **111/111 Windows CTests** and source-governance, history and Git rollback gates before promotion. The active game runtime is not qualified or activated.

## Substantive implemented changes

1. **Replaceable CPU instruction semantics, not game-specific patches.** The Z80 provider preserves register/SP facts across IM and special ED forms, handles the bounded OTIR/OTDR/INIR/INDR and single-step I/O forms without conflating I/O and RAM writes, maintains known B/C/D/E/H/L bytes and 16-bit pairs, models ADD HL,rr and precisely updates CB BIT/rotate registers. Unknown ED operations still terminate as `Z80_ED_SEMANTICS_UNQUALIFIED`. Only the independent Master System machine provider knows which memory writes can alter mapper state. BC=0 repeated 16-bit block moves still count 65536; B=0 repeat-I/O counts 256. No ROM-specific PC checks or hardcoded game identification were added.
2. **Independent 68000 and MIPS improvements.** The 68000 provider now decodes selected PC-relative and register LEA forms, MOVEA immediates, ADDQ/SUBQ long and CLR/TST long, with exact known register updates. MIPS adds safe register-ALU and variable shifts, SLTI/SLTIU and refuses potentially trapping unknown or overflowing signed ADDI; no hardware-specific exception path is invented.
3. **Actual native arithmetic/control-flow proof, not just branch stubs.** The existing source/provider/instruction SHA-attested `analyze-native` route now accepts an opt-in, strictly limited provider-owned register-operation protocol (`set`, `add`, `and`, `or`, `xor`) in addition to jump/next/halt. Native C++ executes and reports synthetic register state for authored Z80 (`A`) and Motorola 68000 (`D0..D7`) proofs, with independent CMake builds after the original image is deleted. Initial registers are **synthetically zeroed**, not reconstructed game machine state; no flags, RAM, video, audio, input, interrupts, or complete CPU semantics. Unsupported operations or the next untranslatable path remain blocked. The production game compiler and v34 standalone exporter are **not** integrated into this probe.
4. **Cross-version byte-attested real-ROM measurement.** The local source development scan of the supplied, unmodified 256 KiB Shinobi input, SHA256 `dac4f1dcb41193cb42a96950444a87c5f2952ea66474c59a38c07b10ac411e47`, with budget 40000 gave **565 static candidates vs 130 in installed v37**. Source-hash-attested comparison: **130 retained, 435 new, 0 missing, 106 reclassified**, with 20 matched return sites; **77 unresolved findings** as the new frontier expands. This establishes **more physical source locations decoded as candidates**, not executable code coverage, verified disassembly semantics, playable output, or fully working Shinobi. The original ROM is **not** bundled in the release. Tests use independently authored fixtures.

```powershell
& $exe analyze --rom 'C:\Roms\MASTERSYSTEM\Shinobi (USA, Europe, Brazil) (En) (Rev 1).sms' --out 'C:\Projects\RecompDev-Evidence\offline-v38-shinobi-real01' --budget 40000 --compare-to 'C:\Projects\RecompDev-Evidence\offline-v37-shinobi-real01'
& $exe analyze-native --rom AUTHORIZED_IMAGE --analysis EXISTING_ANALYSIS --out NEW_SOURCE_TREE --rights-confirmed
```

Every output folder must be new; the controller rejects overwrite, unrecognized formats, plugin/provenance mismatches, source tampering and speculative/incompatible native candidates. `-PublishOrigin` is an already-available **optional** installer switch; this release neither automatically pushes `main` nor changes the existing remote publication policy. Generated game-source publication is a separate repository.

## Acceptance requirements and still-blocked work

The three new CTests cover **12 cross-ISA semantics tests**, **4 native-state compiler/tamper tests** and **a compiled-controller two-system probe test**; all prior tests and documentation/historical checks remain mandatory. An owner MSVC build and **111/111** CTests must pass before the source is installed. Linux may lack the original historical ZIP assets required by two registered tests; a Linux partial result is **not** equivalent to Windows acceptance.

**BLOCKED:** whole-ROM code vs data qualification, precise conditional-flag paths, stack and mapper state in every branch, indirect jump-table resolution, dynamic loading/decompression, broad 68000/MIPS instruction coverage, all-machine native C++ translation from offline discoveries, real standalone game output, and independent graphics/audio/input/hardware parity. New real-ROM candidates must never be described as qualified native game code. The architecture stays universal, with replaceable CPU/format/machine providers and no platform-specific controller branches.
