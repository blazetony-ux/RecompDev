# RecompDev workspace v0.4.9.6 — universal discovery integration

**Date:** 2026-11-05. **Scope:** source-only, controller-mediated and read-only discovery integration. No existing compiled controller/DLL changes. No additional CPU translator and no game-specific source modifications.

## Shipped

- `discovery_integration` v0.1.0; three separately replaceable, registry-selected provider adapters use the frozen historical structure detector, per-source SQLite catalogue (read-only), and ISO9660 2048/2352 sector-aware reader.
- `modular.controller` appends a strict `recompdev.controller.discovery.v1` report alongside the existing discovery report without changing the legacy workflow result. Audit errors are explicit `BLOCKED`, never a fabricated result or native parity claim.
- Validated bounded PS-X EXE static entry and TIM image structural candidates inside disc files; raw candidate export is explicit opt-in and never part of the default ZIP. Discs without those signatures remain undecoded; the historical `RAW_SECTOR_DISC` TIM whole-image scan remains separate and is not silently rewritten.
- Main `CHANGELOG.md` title and historical version ordering corrected, with a new `workspace_governance` 0.1.3 negative-test gate; the obsolete PowerShell wrapper resolves the separately deployed `RecompDev.exe`.

## Breadth and known limitations

- A previous owner Sonic SMS scan prepared 179 functions / 14,170 Z80 instruction candidates but produced no qualified native function; a bounded native run reached 28 frames then recovery was blocked/timed out. These remain cross-game evidence, **not** code-specific instructions for this implementation.
- Owner Mega Drive Sonic and PS1 Ridge Racer discovery runs both returned `DISCOVERY_COMPLETE` with **zero new discovery tasks**, relying on catalogue history. PS1 raw-sector TIM scanning was blocked by the preserved legacy worker; new sector provider can inspect bounded logical files and produce reasoned candidate metadata without claiming universal disc asset extraction.
- This release does NOT implement a universal code discovery scheduler, an active 68000/MIPS CPU DLL, arbitrary disc/archive decompression, per-instruction native translation or reference-frame hardware parity. Fresh-vs-cached reporting is a foundation for those subsequent releases.

## Windows installer correction (WindowsFix1; no release-version increment)

- The initial Windows v0.4.9.6 installation stopped during the 10 discovery-provider tests because a synthetic test fixture opened `working.sqlite` with `with store.connect(...)` and implicitly assumed SQLite would close its file handle. Python connection context managers manage transactions, **not** connection lifetime; Windows correctly raised `WinError 32` when the test temporary directory was removed.
- The fixture now uses `contextlib.closing` and tests that its connection is closed before the temporary files are reclaimed. The actual discovery provider already used `closing` for its read-only catalogue connection; production logic, native translation, Shinobi baseline, and compiled binaries are unaffected.
- This remains an unvalidated v0.4.9.6 source update until all Windows installation and regression gates pass.
