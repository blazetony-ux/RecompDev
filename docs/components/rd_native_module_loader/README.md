# rd_native_module_loader — universal native translation module activation

**Scope:** `production-infrastructure`. **Version:** `0.1.0` (source-only BLOCKED candidate). Registered in `workspace/components.json` and independently tracked by [component changelog](CHANGELOG.md). CMake static library target `rd_native_module_loader`; the translated game instructions themselves reside in separately built shared DLL/`.so` modules.

## Responsibilities and trust boundaries

`RD_NativeBlockV1` (`native_runtime/include/rd_native_block_v1.h`) is a machine-neutral, size/version-checked C interface to execute one already-compiled instruction with an opaque guest state. The `ModuleSet` library validates the supplied exact SHA-256 of the native module, source ROM SHA and length, CPU and semantic IDs, machine and state-layout identity and target ABI; it loads compatible binaries with Windows `LoadLibraryExW` or POSIX `dlopen`. The controller/machine plugin must supply a **trusted expected binary hash** from its compiler/artifact manifest; calculating a hash from an untrusted local DLL is not sufficient independent provenance. Loaded modules are append-only and pinned until host destruction; newer modules get dispatch priority without unloading a currently executing block. A missing instruction returns `0` without modifying guest state; mismatched identity and module failure cannot trigger an interpreter fallback.

The module loader never decodes Z80, 68000, MIPS or SMS instructions and contains no ROM/game identity special case. CPU semantics and bus/mapper/device behaviour remain in their respective plugins. The initial SMS bridge uses a same-toolchain C++ opaque-state representation rather than full portable guest-state serialisation.

## Validation and exclusions

`v04927_native_module_hot_activation` tests two independent compiled native modules, a single persistent host, state continuity, another machine-state instance, strict SHA rejection and CPU/ABI mismatch. `v04927_sms_generated_native_hot_resume` independently exercises actual generated Z80 native instructions with the SMS adapter. The completion candidate now adds `v04927_controller_autonomous_two_hot_recoveries`: a synthetic full controller/Ghidra-test-provider/translator/DLL handshake with two true runtime gaps and same guest process. It also checks immutable source/mapper/binary-context native compiled-module caching (first run MISS, second HIT). A separate Linux synthetic run reached 2,400 frames. Real Win32 persistent window verification, real-ROM 2,400-frame acceptance, and independent gameplay parity remain BLOCKED. Earlier 84/84 Windows foundation results do not validate these completion changes.
