# standalone_export — versioned native application export

**Scope:** `production-workflow` (see authoritative registry `workspace/components.json`). This source component consumes a *pre-existing source-attested generated C++ project* and owner-authorised input data; it never decodes Z80/MIPS/68000 instructions or interprets a ROM. Only source adapters know particular native project layouts. The initial `recompdev.nativepilot-embedded-v1` adapter provides the deliberately narrow transition from the already shipping generated-native-project format.

The controller also provides `RecompDev export demo --out DIRECTORY` for a rights-cleared, synthetic loop that is generated from a preserved test-only fixture. The production exporter does not import that historical test generator.

The controller forwards `RecompDev export build --project PATH --source-data FILE --out DIR --rights-confirmed`; the compiler and Python are build-time dependencies only. Export rejects missing source hashes, incompatible adapters, symlinks, uncontrolled output overwrites, unauthorised embedding, bad source digests or failed native compilation. It compiles a single native application containing the original authorised binary data as a readonly byte array, then tests execution from a directory without the source file or controller. Exported output is a SHA-verified executable, `export-manifest.json`, and instructions; `export verify --bundle DIR` checks unexpected files and mutated executables independently of the developer source tree.

**Do not misstate this capability.** The initial adapter supports one generated-native-source shape, whose generator still has historical dependencies during source generation. The *exporter and exported game* do not invoke the historical generator. The test-proven export on Linux is native and ROM-file-independent. A clean Windows host, independent hardware reference, real gameplay parity and second ISA using the exporter remain **BLOCKED**. Embedding source data eliminates the need to provide a separate ROM file at launch but does **not** remove third-party copyrights or grant redistribution rights; explicit operator confirmation is mandatory.

No source data, ROM bytes, binaries or licensed game content are placed into the source release ZIP, generated-source Git repository or public project documentation. The operator alone can decide to export data they are authorised to distribute. If code coverage is incomplete, the exported generated program is expected to stop at untranslated code rather than silently interpret instructions; neither an export manifest nor a successful bounded run qualifies comprehensive coverage.

Optional `export verify --expected-manifest-sha256 HASH` pins the manifest against an out-of-band trusted SHA-256; verifying a self-reported digest without a trusted pin establishes internal consistency but not publisher authenticity.
