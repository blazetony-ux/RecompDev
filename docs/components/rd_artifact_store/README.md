# rd_artifact_store — universal immutable artifact-provider DLL

**Component scope:** `production-infrastructure`. **Registry:** `workspace/components.json`. **Version:** 0.1.0.

The CPU-, machine-, console- and OS-neutral native component builds as `rd_artifact_store.dll` on Windows and `rd_artifact_store.so` on Linux. `controller/artifact_store_abi.h` exposes a versioned `RD_ArtifactStoreAPIv1` C ABI for producer-selected opaque binary content: kind, producer ID, target ID, ABI tag, bytes and SHA-256. Metadata and payload are separately immutable; repeated identical contents deduplicate, while distinct producer/target descriptors remain isolated. All read/write operations fail closed on invalid entries and hash mismatches.

The controller also invokes the same C++ implementation for a temporary compatibility adapter. For complete eligible recovery sessions, the adapter stores the **actual** attested Ghidra IR, Rizin candidates, reconciled hypotheses, imported observed stops, bank-overlay exports, source-manifest and generated translation sources under immutable content hashes. A controller-private capsule manifest can materialise these bytes into a relocatable, verified history input for existing provider APIs. The original evidence session does not need to remain after successful promotion and acceptance. No old log is consulted for a portable cache hit.

**Boundaries:** The native compiled game binary is **not** stored or executed by the current cache, and `rd_artifact_store` is not a native JIT. A machine-readable compatibility orchestration document remains inside each capsule to support the existing provider contract; this is **not** a dependency on an external historical report. The adapter currently handles the existing Ghidra/Z80 native recovery format; store/ABI supports opaque producer data from MIPS, 68000 and future plugins without assuming those CPUs can yet run. Migration is rejected if the required inputs are missing, source identity differs, a content hash is invalid or a symbolic-link/path traversal is detected. Tool/provider changes may require fresh analysis, even if cached blobs remain portable.

**Storage:** Defaults to user-state `artifact-store/v1` independent of project source, ROM, and diagnostic evidence. `RECOMPDEV_ARTIFACT_ROOT` can specify an absolute alternate root, allowing a full store to move without losing its content addressing. Store objects may be backed up as a directory. Do not delete historical evidence before a real-ROM migration and independent cache-use validation have succeeded.

**Validation:** `v04925_universal_artifact_store`, `v04925_artifact_store_plugin_abi`, `v04925_portable_provider_replay` plus Windows owner full suite and real ROM testing. See [release notes](../../releases/v0.4.9.25.md).
