# Prebuild specification — RecompDev v0.4.9.24

**Date:** 2026-11-08. **Owner request:** build the next version implementing automatic shared reuse of discovered/translated code without manual log selection, retaining universal plugin-neutral architecture. **Installed baseline:** `workspace/v0.4.9.23` Git main `7cdad4fe4fcd5e47818d67e5d51e1f364ebf8488`; Windows 76/76 CTests; 642/642 protected historical source files unchanged. **Release track:** `infrastructure-source` / `git-main-only-no-runtime`; original prebuild v0.4.9.7 and [development contract](DEVELOPMENT-CONTRACT.md) remain authoritative.

## Implementation scope and version boundary

1. **Controller 0.4.20: persistent history registry:** new `controller/recovery_registry.cpp/.hpp` integrated into the compiled `RecompDev` and its C++ controller tests. The registry uses ROM SHA-256 identities to select immutable, verified prior recovery history across jobs and release-version evidence roots; `run --rom` auto-loads eligible history and `cache --rom` inspects it. `--import-history` has explicit precedence; `--no-auto-history` forces fresh generation. No ROM-name tests or SMS/Z80 knowledge enters controller. Cross-ROM bytecode and machine-state are NOT reused merely because an opcode matches. Original translated code remains attached to its source identity; the provider validates full analysis identity and original source bytes again before translation reuse. Registry records are SHA-attested pointers, never compiled code, CPU state, or user logs.
2. **Evidence:** immutable per-session registry records under external Evidence root `translation-registry/v1/<full-ROM-SHA>/`, not source checkout; no modifying older history. Index write is one atomic publish per verified orchestration session. Index lookups bound entries/size and reject symlink/path escapes/hash mismatches. Legacy v23/older evidence is searched read-only within finite scan limits. Index entries are NOT game save states.
3. **Execution monitor 0.4.3:** fix RUNTIME-004: distinguish the 512-KiB diagnostic stdout threshold from a 16-MiB hard limit; extract exactly one bounded, uniquely framed and schema-checked terminal result on a successful native process; preserve the original raw output and explicit oversize metadata. Duplicate, malformed, unsupported schema, nonzero exit and hard-limit overflow fail closed.
4. **Build and governance:** add two CTests for controller recovery registry and strict stdout, plus extend compiled job-manager mock for transparent history re-use. Preserve original 642 historical bytes. Update top-level and component changelogs, roadmap/handover, this prebuild, release notes and manifest. No new PowerShell/Python production orchestration layer; the strict preview parser is existing Python diagnostic adapter; the main registry is native C++.

## Explicit exclusions, independent acceptance and rollback

**Not claimed:** persistent native binary DLL cache, in-process hot-loading, dynamic new CALL/RET dispatch, paused game-state continuation, full CPU/RAM/VDP/APU mapper checkpoint, deterministic timestamped input replay, original-ROM-free production game, Mega Drive/PS1 compiled execution or independent gameplay parity. Do not silently run an interpreter to compensate for missing native code. Future `TRANSLATION_REQUIRED` plus hot-loading design must supply the required contract and fully attested state capture or replay before enabling live continuation.

Acceptance: full GCC/Ninja build + focused C++ registry and end-to-end job-manager tests, Python strict stdout negative controls, docs governance, Windows MSVC **78/78 CTests**, all **642 original files** unchanged, independent user proof of auto-cache hit on Bank Panic and Alex Kidd with real analyzer source/tool attestations, and neutral 2,400-frame Shinobi preview showing `FRAME_BUDGET_REACHED` alongside >512-KiB stdout disclosure instead of falsely returning `NO_NATIVE_RESULT`. Windows real ROM reference gameplay/video/audio/input parity remains unqualified. Installer `-Mode Validate` only stages a dev checkpoint; owner `-Mode Install` after a clean gate promotes Git main, creates immutable tag/verified rollback bundle but leaves active production runtime untouched. No remote push or console-specific controller changes.
