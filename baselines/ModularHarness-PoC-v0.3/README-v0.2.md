# RecompDev Modular Harness PoC v0.2

## Purpose

Demonstrate genuine RecompDev v0.4.0.45 Ghidra P-code export -> source-byte-attested C++ lowering -> dynamically loaded shared library -> bank-aware hybrid execution -> discovery evidence, without changing v0.4.0.45 or v0.1.1.

**Status:** Linux-compiled, 18/18 CTest pass (see `VALIDATION_RESULTS-v0.2.json`). Windows source build **not yet tested by the authoring environment**; use `WINDOWS-v0.2-QUICKSTART.md`.

## New since v0.1.1

- Production code is reused verbatim from v0.4.0.45: `vendor/RecompDev-v0445/nativepilot/generator.py` (`verify_export`, `emit_instruction`) and `z80_cycles.hpp`.
- A deterministic synthetic `recomp-function-pcode-v1` sample includes a bank 3 overlay, generated by `tools/make_pcode_sample.py` (matching the v0.4.0.45 native execution test's export shape).
- `tools/build_pcode_plugin.py` checks whole-source SHA256, *each* instruction hash, physical-bank provenance and P-code support; unsupported instructions are **excluded and recorded** rather than fabricated.
- Generated C++ is a real `RD_GAME` DLL (`rd_game_recomp_v0445`) using the generic `RD_Bus` contract and v0.4.0.45 lowering semantics. `rd_pcode_bridge.hpp` maps production register offsets to the PoC CPU state, with explicit bounds and omissions.
- `--case rom --rom PATH --game rd_game_recomp_v0445` loads an external development ROM; the host requires the DLL's embedded whole-image SHA-256 **and length** to match before executing.
- The provided sample executes **8 generated native instructions, 2 interpreted instructions**, transitions native -> fallback -> native, switches mapper bank, emits JSONL evidence/PPM/WAV and passes PoC reference state comparisons.
- Standard SHA256 vectors and forged export/wrong ROM fail-closed tests.
- Existing 12 v0.1.1 tests are retained.

## Limitations / honest qualification

The included "Ghidra-format" sample was **constructed**, not exported by Ghidra from a commercial game. No owner-local real Ghidra export was supplied, so **real-game native translation and gameplay are not established**. The integration with the authentic v0.4.0.45 translator is real, but the sample instruction bodies are synthetic. The CPU plugin interprets a small subset, and the game code adapter only handles basic AF/BC/DE/HL/SP registers (no IX/IY, shadow registers, interrupts, etc.). This is **not** a universal Z80 backend; emitted code that depends on unmodelled state must be rejected. Timing is decoded by the original `z80_cycles.hpp` and rejects unknown encodings.

The Master System plugin uses v0.4.0.45 runtime. Display and audio are diagnostic file sinks (PPM/WAV), not interactive game display. Interpreted paths still depend on a development ROM, not a ROM-free release. Matching the PoC interpreter does not prove parity with independent emulation hardware. No ROM, game source file, or production catalogue is modified. Replacing the generated sample source changes only this isolated PoC folder.

## Generate the game DLL from owner-local evidence

```bash
python3 tools/build_pcode_plugin.py \
 --rom /path/to/owner.sms --export /path/to/functions.json \
 --bank-export /path/to/slot2-bank3-functions.json \
 --out generated/rd_game_recomp_v0445.cpp
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target rd_game_recomp_v0445 RecompDevHarness
./build/bin/RecompDevHarness --plugin-dir ./build/bin \
 --game rd_game_recomp_v0445 --case rom --rom /path/to/owner.sms \
 --steps 20 --out ./build/reports/owner
```

A separate SQLite sidecar can be created by the preexisting v0.1.1 `tools/import_discovery.py`. All default paths are local to the PoC.

## Release gate

- **Pass:** ABI load, physical bank dispatch, generated native state changes, fallback and resumption, PoC differential parity, strict ROM SHA256 check, evidence export.
- **Not passed:** actual Ghidra export from owner game, cross-system host validation, full Z80 instruction/interrupt parity, strict native-only game, complete asset extraction, Windows compiled validation.
